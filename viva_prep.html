Say this first

The 2-minute pitch

Normally, if you want a language model to write differently, you either change what you ask it (the prompt) or you retrain it. My project does neither. It changes the model's "thoughts" while it is writing.

Inside the model, every word is held as a long list of numbers. Ideas like "happy" turn out to be a direction in those numbers. I find that direction by showing the model pairs of sentences that differ only in mood ("I loved the trip" / "I hated the trip") and taking the difference. Then, while the model writes, I add a bit of that direction at every word. The text becomes happier, or sadder if I subtract it. As a fair test, I also add a random direction of the same size, which should do nothing.

I tried this on two models: Qwen, a ready-made model with half a billion parameters, and TinyGPT, a small 12-million-parameter model that I wrote and trained myself in 18 minutes on children's stories. On Qwen the mood goes from neutral (+0.05) to clearly happy (+0.85) or sad (−0.46), while the random direction does nothing. It works better than simply asking for a happy story, and five example pairs are enough.

Because I trained TinyGPT myself, I could also ask when during training the model learns the idea of happy vs sad. It happens suddenly, at about 4% of the way through training. And it works for other ideas too: rich or poor, old or young, huge or tiny. You can even add two ideas together: "huge" plus "magic" gives a dragon.

Five things to say, in order: the idea (change its thoughts, not the prompt) → how (difference of example sentences, added while writing) → the two models → the results → what's new (when it's learned, other ideas, adding ideas).
The idea

What is steering?

A language model reads text one piece at a time and keeps, for each piece, a long list of numbers that holds "what it has in mind" at that point: 896 numbers in Qwen, 384 in TinyGPT. This list is called the residual stream.

The model is built as a stack of layers. Each layer looks at that list, works something out, and adds its result back onto it. So the list is like a shared notebook that every layer reads and writes into. If I write something into the notebook at one layer, every later layer sees it.

Researchers have found that many ideas, like happy vs sad, correspond to a direction in this list of numbers. So if I know the direction for "happy", I can nudge the model's notebook that way while it writes, and it writes more happily. Nothing in the model is changed permanently, and the prompt stays exactly the same.

One-line answer: "Steering means nudging the model's internal state towards an idea while it writes. The idea's direction comes from the difference between example sentences with and without it. Nothing is retrained and the prompt isn't changed."

Compared with the usual ways

  • Prompting (asking nicely): free, but a basic model like Qwen often ignores instructions, and the effect is weaker.
  • Fine-tuning (retraining): strong, but needs data and computing time, and changes the model for good.
  • Steering: cheap (a few seconds to find the direction), adjustable with one number (how hard to push, and which way), and the model goes back to normal afterwards. The price: push too hard and the text stops making sense.
How

How it works, step by step

  1. Write example pairs that differ only in the idea: "I loved the trip, it was wonderful" / "I hated the trip, it was awful". For Qwen: 150 pairs (10 word pairs in 15 sentence patterns). For TinyGPT: 72 simpler pairs in children's-story style, because it only knows simple English.
  2. Look inside: feed every sentence to the model and record its notebook (the list of numbers) after each layer, for every word. The very first word is skipped, because models always give it unusually large numbers.
  3. Find the direction: average the happy sentences' numbers, average the sad ones, and subtract. That difference is the "happy direction". There is one for each layer.
  4. Nudge while writing: a small piece of code attached to one layer (a hook) adds the direction to the notebook at every word, as the model writes. A number called α (alpha) sets how hard: +8 means eight times the happy direction, −8 means eight times towards sad. Afterwards the hook is removed.
  5. Fair test: do the same with a random direction of exactly the same size. If that also changed the mood, the effect would just be "any push changes the text". It doesn't.
  6. Judge the result on lots of short continuations: 50 everyday prompts for Qwen ("I went to the market today and"), 30 story openings for TinyGPT ("Tom had a red ball. He"), two samples each.
Built from scratch

TinyGPT: the model I built

A 12,194,688-parameter decoder-only GPT written in PyTorch (tinygpt/model.py), with its own tokenizer and training loop. Each component is a deliberate, modern choice, the same family as Llama and Qwen.

BPE tokenizer, vocab 4,096

trained on TinyStories

Byte-level BPE merges frequent character pairs into tokens. A small vocabulary fits a children's-story corpus; GPT-2's 50k vocabulary would put ~19M parameters in the embedding alone, more than the whole model.

Token embedding (tied)

4,096 × 384 = 1.57M params

Maps each token id to a 384-number vector. The output layer reuses the same matrix (weight tying), saving 1.6M parameters.

RoPE (rotary position embedding)

Su et al. 2021

Rotates query and key vectors by an angle that depends on position, so the attention score depends on the relative distance between tokens. No learned position table.

RMSNorm

Zhang & Sennrich 2019

Rescales each vector to unit root-mean-square, with a learned gain. Like LayerNorm without subtracting the mean: simpler and as good.

Pre-norm

x + f(norm(x))

Normalise before each sub-layer and add the result to the untouched x. This keeps a clean residual path, so training is stable without careful warm-up, and it is the "stream" that steering edits.

Causal self-attention, 6 heads

4 × 384² = 590k params per block

Each token attends only to earlier tokens (causal mask). 6 heads of 64 dimensions. Uses PyTorch's fused scaled-dot-product attention (tested against an explicit implementation).

SwiGLU feed-forward, hidden 1,024

Shazeer 2020 · 3 × 384 × 1,024 = 1.18M per block

A gated MLP: W2(silu(W1 x) ⊙ W3 x). Standard in modern LLMs; with hidden 1,024 it has about the same parameters as a 4× GELU MLP.

Residual stream, width 384

6 blocks, context 256 tokens

Every block adds its output to a running vector per token. Steering adds α·v to it after a chosen block.

Training

  • Data: 500k TinyStories tokenized (115M tokens); the run used 80M: 4,882 steps × 64 × 256 tokens.
  • Optimiser: AdamW, lr 1e-3, betas 0.9/0.95, weight decay 0.1; 200 warm-up steps then cosine decay to 10%; gradient clipping 1.0; fp16 mixed precision.
  • Hardware: one free Kaggle T4, about 86k tokens/s, 18 minutes.
  • Result: validation loss 1.67 (perplexity 5.3); coherent stories ("Lily … went to the park to play with her friends … saw a pretty butterfly").
  • Checkpoints every 500 steps; for E6 the first 600 steps were re-run with the same seed and schedule, saving every 50 steps. The re-run reproduced the original validation losses (2.861 at step 250, 2.412 at 500).
  • Also supported, not used in the final run: learned / sinusoidal / ALiBi / no position encoding, LayerNorm, post-norm, GELU, grouped-query and multi-query attention. 52 unit tests cover parameter count, causality, fused vs explicit attention, longer-than-training contexts, and overfitting a batch.

Why TinyStories?

Eldan & Li (2023) showed that models under 10M parameters can write fluent stories if the data uses only words a 3–4-year-old knows. That lets a from-scratch model train in minutes and still produce text worth steering. The price: TinyGPT only knows children's English, so many concepts (economics, old people) don't exist for it.

The ready-made model

Qwen: the ready-made model

Qwen2.5-0.5B is a free model from Alibaba, with about half a billion parameters and 24 layers, trained on a huge amount of web text. I used the base version, not the chat version: it just continues text and doesn't follow instructions.

  • Why this one? Small enough to run on a laptop, and well known.
  • Why the base version? Because it doesn't follow instructions, comparing "steering" with "asking for a happy story" is a real test.
  • Its odd habit: it often turns text into exam questions ("A. B. C. D. Answer:"), because it saw a lot of quiz data in training. In the live demo I block Chinese characters and "____" blanks for this reason; the experiments had no such filter.

Measuring

How we judged the results

  • How happy is the text? A separate, ready-made mood classifier (a model trained to rate the sentiment of tweets) gives each text a score from −1 (sad) to +1 (happy). It's independent of the models being steered, so they can't "mark their own homework". I first tried a two-option classifier, but it called neutral sentences sad ("The train leaves at 5 pm" → 63% negative), so I switched to one with a neutral option.
  • Does it still read well? I let the normal, unsteered model read the steered text and measure how surprised it is (perplexity: lower means more natural). Normal Qwen text scores about 3.6. If it gets above three times that, I count the text as broken.
  • Is it repeating itself? I count how many word pairs are different (distinct-2). Repetitive loops can look "unsurprising" to the model, so this catches them.
  • Can the idea be read at this layer? I take 40 natural sentences ("My dog died yesterday") and check whether the happy direction tells the happy ones from the sad ones (probe score: 0.5 = guessing, 1.0 = perfect).
  • Picking the best setting: the layer and strength that move the mood furthest in both directions while the text still reads well. This was chosen automatically, not by me.
  • For other ideas (rich/poor, etc.), there is no ready-made classifier, so I read the texts myself. The demo also shows a concept score: how far along the idea's direction the model places the text. It's useful, but it uses the same direction as the steering, so it can be fooled.

E1 · Where to steer (Qwen)

Without steering, Qwen's text is neutral (+0.05). Steering at layer 4 makes it clearly happy (+0.85) or sad (−0.46). The random push stays between −0.10 and +0.29: no consistent direction.

The interesting part: the idea is easiest to read in the middle layers (9–14, probe score 0.99), but easiest to push at an early layer (4). Where you can see an idea is not where you can best change it. A push early on has 20 more layers to turn it into happier word choices.

E2 · How hard to push

The effect grows with strength, then levels off. The text gets harder to read as you push: past about 8–12 it starts looping ("I looked at the world, I looked at the world…"). Pushing towards sad even gets weaker at the extreme (−0.62 at strength 12, only −0.51 at 16), because broken text isn't really sad, just broken.

E3 · Steering vs simply asking (Qwen)

TowardsNothingAskingSteeringBoth
happy+0.05+0.50+0.85+0.96
sad+0.05−0.14−0.46−0.64

"Asking" means starting the text with "The following is a happy, cheerful story full of joy." Steering moves the mood about twice as far; asking keeps the text more natural. Use both for the strongest effect.

E4 · How many examples

With only 5 example pairs, steering is already almost as strong as with all 150 (+0.80 / −0.56 vs +0.85 / −0.46). A rough direction is good enough to steer.

E5 · My tiny model

TinyGPT also has a clear happy/sad direction at every layer. It's already cheerful on its own (+0.48, because children's stories end happily). Steering at layer 4 gives +0.93 or −0.56. A model I trained in 18 minutes behaves like one 40 times bigger.

E6 · When the idea is learned

I went back through TinyGPT's training snapshots and, at each one, rebuilt the happy direction and tried steering with it.

  • Up to step 150: no happy/sad direction at all (probe score at guessing level), and steering does nothing.
  • Between steps 150 and 250 (about 4% of training): the direction suddenly appears (probe score jumps from 0.46 to 0.91) and steering starts working.
  • After that: steering towards happy is almost at full strength by step 300; towards sad keeps getting stronger until about step 2,000.
How to explain it: "The model first learns which words are common, and only once it starts learning how sentences fit together does it pick up an idea like mood. That switch happens quickly." I'd add that it's one training run, so it should be repeated before calling it a general rule.
Beyond happy and sad

Other concepts

The same method works for many ideas. Each one needs just six matched example pairs, such as "We flew to Paris on our private jet" / "We could not afford the bus fare".

Five lessons from these

  1. The direction picks up everything that differs between your examples. My "uncertain" sentences were also longer and ended with "?", so "confident" just meant "short, flat statements". My first cat sentences also had cats purring, drinking milk and climbing trees, so steering gave owls in trees and "tea tea tea", but never a cat. Making the pairs differ only in the animal fixed it.
  2. You can only steer towards things the model has seen. There are almost no old people in children's stories, so "old" doesn't work on TinyGPT. If one side is already the model's default (American, happy endings), only the other side moves.
  3. Ideas about content work; grammar doesn't. Wealth or age can change a whole scene. Tense depends on a few small words ("will", "-ed") in exactly the right place, and a push at every word scrambles them.
  4. The prompt has to leave room for the idea. "There was a young girl" gives greedy-vs-sharing nothing to share. "Lily found a ball… her friend asked to play. Lily…" works.
  5. There's a sweet spot. French comes out best at medium strength. Push harder and it breaks, the same as in E2.
Combining

Mixing two concepts

I added two directions at the same time and made a 3×3 grid: one idea down the side, the other across the top, with plain text in the middle. TinyGPT, starting with "Tom went for a walk in the woods. Suddenly, he saw a":

everyday(neither)magic
hugebig, hungry…big scary monster!huge giant giant dragon!
(neither)a big, red applebig bear! (no steering)a shiny stone. It was magical!
tinya big, red applea small rabbita tiny creature… "I'm tiny fairy"
  • None of my example sentences mention a dragon or a fairy. The model combined the two ideas itself: something both huge and magic is a dragon, something tiny and magic is a fairy. It's like the famous word-vector trick "king − man + woman ≈ queen".
  • It works because the two directions are almost independent (they point in unrelated directions), so each changes only its own idea.
  • On Qwen, "poor + old" gave "so poor that he cannot buy anything… I give him a piece of bread", and a house became "very dilapidated… I am lonely… I am cold". "Rich + old" was weaker: it read mostly as old.
  • I use a medium strength (6) for each idea, because two pushes together add up to a bigger push.
Surprises

Interesting observations

  • Seeing an idea isn't the same as changing it. The idea is clearest in the middle layers, but steering works best early on.
  • Happy is easier than sad in both models. Most text the models learned from leans positive.
  • To TinyGPT, "sad" means scary and loud: "He thought loud loud so loud mean loud noises or scary…". In children's stories, bad things are loud dogs and broken toys, not grief. What a direction means depends on what the model read.
  • Happy steering makes TinyGPT end its stories sooner: the chance of ending jumps from 5% to 26% at strength 8 and 36% at 12. Happy endings are where stories stop.
  • The idea is learned suddenly during training, not slowly.
  • Qwen loves quizzes: short prompts often turn into multiple-choice questions, with or without steering.
  • Cats turned into owls and tea: the first examples taught the wrong thing. "per per per" was the start of "purred".
  • The model's default world is American: steering towards Indian works, towards American hardly changes anything.
  • Ideas can be added: huge + magic = dragon.
  • Tone slides, topic switches: formal ↔ casual changes step by step; food ↔ sports only flips at full strength.

Demo plan (about 5 minutes)

Before the viva: start the demo 10 minutes early (the first click takes a while to load), check the link on a phone, and keep the laptop plugged in. If the live demo fails, the project page's replay always works.

  1. Project page: the headline numbers, then the training slider. Drag from step 100 to 250 and show the idea appearing.
  2. Steer tab (Qwen, happy ↔ sad, strength +8, "I went to the market today and"): show plain vs steered vs random side by side, then try −8.
  3. Transition tab (Qwen, rich ↔ poor, "For dinner tonight, my mother", seed 1): one prompt at five strengths, from not enough rice to a five-star hotel.
  4. Mix tab (TinyGPT, huge ↔ tiny × magic ↔ everyday, "Tom went for a walk in the woods. Suddenly, he saw a", strength 6, seed 1): the dragon and the fairy. The page also switches to a storybook look for TinyGPT.
  5. Concept meter: colour each word of a mixed sentence ("The party was wonderful, but then my dog got sick…") by how happy or sad the model thinks it is.
  6. Let the examiner try their own prompt or idea.
If a live result looks odd: first look at the "no steering" row, since the model might already lean one way. If the text repeats or breaks, lower the strength to 4–6. If nothing changes, make the prompt stop right where the idea would show up. If the wrong thing appears, check the two example boxes differ only in the idea. Different tabs can give different text for the same seed: they sample differently.
Strengths

What went well

  • A fair test every time: each result is compared with a random push of the same size, using the same prompts.
  • An independent judge for mood, and the cost to readability reported next to every result.
  • Building my own model made the "when is it learned" question possible, which you can't ask of a ready-made model.
  • Repeatable: re-running the start of training gave exactly the same numbers, and the demo gives the same text for the same settings.
  • Cheap: about 2 hours of free Kaggle time; everything else on a laptop.
  • Honest about failures: tense, confident, cats and old-on-TinyGPT are kept and explained.
  • Deployed for free: an always-on project page plus a live demo from the laptop.
Be honest

Limitations and assumptions

Limitations

  • The "learned suddenly" result comes from one training run. It should be repeated with other random starts and model sizes.
  • Only mood has an independent judge. The other ideas were checked by reading a few examples.
  • The demo's concept score can be fooled, because it uses the same direction as the steering.
  • The mood classifier was trained on tweets and can misjudge strange or broken text.
  • Small samples: 100 texts per setting for Qwen, 60 for TinyGPT, so small differences are noise.
  • Steering costs readability: at the best setting, the text is about three times less natural.
  • Two small models only: it may behave differently in big chat models.

Assumptions

  • Ideas like happy/sad are directions in the model's numbers.
  • The difference between example sentences captures the idea, not something else (the cat story shows when it doesn't).
  • Adding the same push at every word is a reasonable way to steer.
  • The normal model's surprise is a fair way to judge readability, and three times normal is a sensible limit.
  • "Layer 4" means roughly the same thing in both models (early on in both).
Takeaways

What I learned

  • Ideas really are directions inside a model, and a handful of examples is enough to find them.
  • Where you can see an idea is not where you can best change it.
  • Good examples beat many examples: the direction learns every difference you put in.
  • What a model can be steered towards, and what an idea means to it, comes from its training data.
  • Models can pick up an idea suddenly during training.
  • Always use a fair comparison (the random push), and report the cost next to the effect.
  • Building a model from scratch made every part of a transformer concrete for me.
Next

What else could be tried, and what I'd add

Could have tried

  • Repeat the training study with more random starts and model sizes.
  • Do the training study for other ideas: are size or wealth learned at a different time than mood?
  • An independent judge for every idea (a classifier or a big language model) instead of reading by eye.
  • Gentler steering: push only on some words, or at several layers a little each, to keep the text more natural.
  • Bigger and chat models, and safety-related behaviours like refusing or flattering (as in the paper this method comes from).
  • Finding directions automatically (sparse autoencoders) instead of writing example pairs.

What I'd add to the demo

  • A readability number on every output, so you can see the cost live.
  • Subtracting ideas, and mixing more than two.
  • A view of the same prompt steered at every layer side by side.
Story

How the project evolved

  1. I started with "build a tiny GPT and compare 11 design choices". It felt too common, and 33 training runs was a lot.
  2. I switched the focus to steering, which is more interactive and makes a better demo. TinyGPT stayed as my own model, and that made the "when is it learned" study possible.
  3. I ran training and all experiments on Kaggle, then re-ran the first 600 steps with frequent snapshots when I saw the jump happened early.
  4. Hugging Face now charges for hosting live demos, so I made a free always-on page plus a live demo from my laptop.
  5. Trying the demo myself led to the other ideas and the mixing study, and to finding what didn't work (cats, confident, sunny vs rainy, which I dropped).
Practice

Likely viva questions

What is your project, in one sentence?

I change what a language model writes by nudging its internal state towards an idea while it writes, I test it on a ready-made model and on a small model I built myself, and I use my own model's training to see when the idea is learned.

What is the residual stream, and why do you change it there?

It's the list of numbers the model keeps for each word, like a shared notebook. Every layer reads it and adds its own result onto it. So if I add something to it at one layer, all the later layers see it. That makes it the natural place to nudge.

How do you find the "happy" direction?

I feed the model happy sentences and matching sad sentences, record its numbers at a layer, average each group and subtract. What's left is the direction that separates happy from sad.

Why skip the first word?

Models always give the very first word unusually large numbers, whatever it is. Including it would drown out the actual difference between happy and sad.

What does the strength (α) mean, and why 8?

It's how many times I add the direction: +8 is eight times towards happy, −8 eight times towards sad. 8 was picked automatically: the strongest effect in both directions while the text still reads well.

How do you know it's really the idea, and not just any push?

I always also add a random direction of exactly the same size. It changes some words but doesn't move the mood in any consistent direction (it stays around zero), while the happy direction moves it clearly (+0.85 or −0.46).

Why is layer 4 best for steering, if the idea is clearest at layers 9–14?

Seeing and changing are different. A nudge early on passes through 20 more layers, which turn it into happier word choices. A nudge late has little room left to make a difference. Late layers still push towards happy, but not well towards sad.

Isn't this just a stronger prompt?

No, the prompt never changes. And it works where asking doesn't: Qwen's base version doesn't follow instructions, so asking for a happy story only reached +0.50, while steering reached +0.85. Together they reached +0.96. Asking keeps the text more natural, though.

Why does pushing harder sometimes give less effect?

Push too hard and the numbers end up somewhere the model has never been, so the later layers can't turn them into proper sentences. The text starts repeating and becomes nonsense, which isn't really sad or French any more, just broken.

Why is happy easier than sad?

Most of what the models learned from leans positive (children's stories almost always end happily), so happy text is closer to "normal". Pushed hard towards sad, they start looping before they get really sad.

Explain the "learned suddenly" result.

Using TinyGPT's training snapshots, I rebuilt the happy direction at each one. Until step 150 there is none and steering does nothing; by step 250 it's clear and steering works. That's about 4% of training. My reading: the model first learns which words are common, then quickly picks up higher-level ideas like mood once it starts learning how sentences fit together. It's one run, so it should be repeated.

How do you know the re-run of early training matches the original?

Same random seed, same data order and same settings, just stopped at step 600. Its error score on held-out stories (validation loss) matched the original run at steps 250 and 500: 2.861 and 2.412.

What is the probe score?

A check of whether the idea can be read at a layer: I take 40 ordinary sentences, 20 happy and 20 sad, and see if the happy direction sorts them correctly. 0.5 means guessing, 1.0 means perfect.

Why that mood classifier?

It has a neutral option, so neutral text scores near zero. The one I tried first only had happy or sad, and called ordinary sentences sad, which would have hidden the sad results.

How do you measure whether the text still reads well?

I let the normal, unsteered model read the steered text and measure how surprised it is (perplexity). If it's more than three times its usual surprise, the text counts as broken. I also count repeated word pairs, because loops can look unsurprising.

Walk me through TinyGPT.

BPE tokenizer with 4,096 tokens → 384-dimensional embedding → 6 pre-norm blocks, each RMSNorm → causal attention with 6 heads and RoPE → add, then RMSNorm → SwiGLU MLP (hidden 1,024) → add → final RMSNorm → output layer tied to the embedding. 12,194,688 parameters, trained on 80M TinyStories tokens in 18 minutes with AdamW and a cosine schedule, validation loss 1.67.

Why those particular parts (RoPE, RMSNorm, SwiGLU)?

RoPE: rotates q and k by position, so attention depends on relative distance, with no position table. RMSNorm: normalises by root-mean-square without subtracting the mean; simpler than LayerNorm, same quality. SwiGLU: a gated MLP that beats GELU at equal parameters. Pre-norm: a clean residual path and stable training. They're the choices modern LLMs (Llama, Qwen) use.

Why only 4,096 word pieces?

TinyStories has a small vocabulary, so 4,096 BPE tokens cover it. With GPT-2's 50k vocabulary the embedding alone (50k × 384) would be about 19M parameters, more than the whole model.

How many examples do you need?

Five pairs already give nearly the full effect. But good examples matter more than many: the cat examples show that.

Why did "confident" and the first "cats" fail?

The direction learns everything that differs between the two sets. The uncertain sentences were longer and ended with "?", so "confident" became flat statements. The cat sentences also had cats purring, drinking milk and climbing trees, so steering gave owls and tea. Making the pairs differ only in the animal fixed it.

Why does old ↔ young work on Qwen but not TinyGPT?

You can only steer towards what the model has seen. Children's stories have almost no old people; Qwen read the whole web.

Why doesn't tense work?

Tense depends on a few small words in exactly the right place. A push at every word scrambles the grammar. Ideas about what the text is about, like wealth or age, can change a whole scene and survive.

How does mixing two ideas work?

I add both directions at once. They point in nearly unrelated directions, so each changes only its own idea. The model fills in something that fits both: huge + magic gives a dragon, tiny + magic a fairy, even though none of my examples mention either. Like "king − man + woman ≈ queen".

Why do the rows in the Transition tab start the same and then split?

All rows use the same random choices, so the only difference between them is the steering. They write the same words until the push changes one word choice, and then each follows its own path.

How is it deployed?

An always-on project page on Hugging Face (free) with the results, graphs and replays of real outputs, plus the live demo running on my laptop with a public link. The demo puts its link on the project page automatically. Hugging Face now charges for hosting live demos, so this keeps it free.

What are the main limitations?

The "learned suddenly" result is from one training run; only mood has an independent judge; small samples; steering costs readability; only two small models.

Is this like anything you've studied before?

Yes: moving along a direction in an image model's hidden space to morph one face into another. The Transition tab is the text version of that. And mixing ideas is like word-vector arithmetic (king − man + woman).

What would you do with more time?

Repeat the training study with more runs and for other ideas, add an independent judge for every idea, try gentler steering to keep text natural, and test bigger chat models.

How did you use Claude Code?

As a coding partner for most of the code. I chose the direction (from comparing designs to steering), ran everything on Kaggle, decided the experiments and how to deploy, and tested the demo myself. That testing found real problems: the cat side never gave cats, sunny vs rainy was weak (dropped), and the mixing examples were too similar.

What was the hardest part?

Choosing honest ways to measure (my first mood classifier and first probe both looked fine but were wrong), and getting ideas other than mood to work, which needed carefully matched examples and prompts that leave room for the idea.

Glossary

SteeringNudging a model's internal state towards an idea while it writes
Residual streamThe list of numbers kept for each word, which every layer reads and adds to (the "shared notebook")
Direction / vectorA list of numbers that points towards an idea, like "happy"
Example pairsTwo sentences that differ only in the idea ("loved" / "hated")
HookA small piece of code attached to a layer that changes its output as the model runs
Strength (α)How many times the direction is added; the sign picks the side
ParametersThe numbers a model learns during training (12.2 million in TinyGPT)
LayerOne step in the model's stack of processing
Tokenizer / tokenWhat splits text into pieces / one piece
AttentionThe part that lets each word look back at earlier words
Feed-forward (SwiGLU)The part that processes each word on its own, with a gate
RoPEThe way TinyGPT knows where each word is and how far apart words are
RMSNormKeeps the numbers at a steady size so training is stable
ProbeA test of whether an idea can be read from a layer
PerplexityHow surprised the model is by a text; lower = more natural
ClassifierA model that sorts text into categories (here: negative, neutral, positive)
SeedThe starting point for random choices; same seed = same output
Base vs chat modelA base model just continues text; a chat model is trained to follow instructions
