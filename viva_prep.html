Say this first

The 2-minute pitch

We usually control a language model from the outside: change the prompt, or fine-tune the weights. Activation steering controls it from the inside. If a concept like "happy" is stored as a direction in the model's hidden states, then adding that direction while the model writes should make the text happier, with no training and no prompt change.

I build the direction from contrastive pairs ("I loved the trip" / "I hated the trip"): the average hidden state of the happy sentences minus the average of the sad ones, at one layer. A PyTorch forward hook adds α × vector to the residual stream at every token. A random vector of the same length is the control.

Two models: Qwen2.5-0.5B (pretrained) and TinyGPT, a 12.2M-parameter GPT I wrote and trained from scratch on TinyStories in 18 minutes. On Qwen, steering at layer 4 moves sentiment from +0.05 to +0.85 and to −0.46; the random vector does nothing. Steering beats asking for a happy story, and five pairs are enough.

Novelty: because I trained TinyGPT myself, I could ask when the concept appears. It's sudden: between training steps 150 and 250, about 4% of training. It also works on other concepts (wealth, age, size, language), and two vectors can be added: huge + magic gives a dragon.

Five beats, in order: what (steer from inside) → how (contrastive vector + hook) → two models → results (+0.85, random does nothing, beats prompting) → novelty (sudden emergence, other concepts, vectors add).
Concept

What is activation steering?

A decoder-only transformer keeps one vector per token: 896 numbers in Qwen, 384 in TinyGPT. This is the residual stream. Every block reads it, computes attention and a feed-forward update, and adds the result back:

x ← x + attention(norm(x))
x ← x + feedforward(norm(x))

Because every block writes into the same space by addition, a vector added at one layer is carried forward to every later layer. That makes the residual stream the natural place to edit.

The linear representation hypothesis (Park et al., 2024) says many high-level concepts are directions in this space. If "happy vs sad" is a direction, then the difference between the average hidden state of happy text and of sad text points along it, and adding it pushes the model towards happy.

One-line answer: "Steering adds a concept direction to the model's hidden state while it generates. The direction is the average difference between hidden states of examples with and without the concept. Nothing is trained: the weights and the prompt stay the same, and the hook is removed afterwards."

How

The method, step by step

  1. Contrastive pairs. Sentences that differ only in the concept. Qwen: 10 word pairs (loved/hated, wonderful/awful, …) in 15 templates = 150 pairs. TinyGPT: 6 word pairs in 12 TinyStories-style templates = 72 pairs (TinyGPT only knows simple children's English).
  2. Read hidden states. Run every sentence through the model; record the residual stream after every block at every token. Skip each text's first token, which has unusually large activations, and padding.
  3. Steering vector per layer: v_ℓ = mean(happy tokens) − mean(sad tokens). For Qwen layer 4, |v| ≈ 1.1, used at its natural size, so α is a multiple of the real happy–sad gap.
  4. Steer. A forward hook on block ℓ replaces its output h with h + α·v at every position and every new token. α > 0 → happy, α < 0 → sad. The hook is removed afterwards.
  5. Control. Repeat with a random Gaussian vector rescaled to |v|, same layer and α. Separates "the concept moves the text" from "any push of this size moves the text".
  6. Measure sentiment, fluency and repetition on 40 new tokens (temperature 0.7, top-p 0.9), 2 samples per prompt: 50 neutral prompts for Qwen, 30 story openings for TinyGPT.

The hook, in code (steer/core.py)

@contextmanager
def steering(self, layer, vector, alpha):
    add = (alpha * vector).to(self.device, self.dtype)
    hook = self.layers[layer].register_forward_hook(
        lambda m, inp, out: _replace_hidden(out, _hidden(out) + add))
    try:
        yield
    finally:
        hook.remove()

The same code steers both models: Qwen's blocks are model.model.layers, TinyGPT's are model.blocks. For a batch, vector can hold one vector per row, so steered, unsteered and random rows are generated together and differ only in what is added.

Built from scratch

TinyGPT and its components

A 12,194,688-parameter decoder-only GPT written in PyTorch (tinygpt/model.py), with its own tokenizer and training loop. Each component is a deliberate, modern choice, the same family as Llama and Qwen.

BPE tokenizer, vocab 4,096

trained on TinyStories

Byte-level BPE merges frequent character pairs into tokens. A small vocabulary fits a children's-story corpus; GPT-2's 50k vocabulary would put ~19M parameters in the embedding alone, more than the whole model.

Token embedding (tied)

4,096 × 384 = 1.57M params

Maps each token id to a 384-number vector. The output layer reuses the same matrix (weight tying), saving 1.6M parameters.

RoPE (rotary position embedding)

Su et al. 2021

Rotates query and key vectors by an angle that depends on position, so the attention score depends on the relative distance between tokens. No learned position table.

RMSNorm

Zhang & Sennrich 2019

Rescales each vector to unit root-mean-square, with a learned gain. Like LayerNorm without subtracting the mean: simpler and as good.

Pre-norm

x + f(norm(x))

Normalise before each sub-layer and add the result to the untouched x. This keeps a clean residual path, so training is stable without careful warm-up, and it is the "stream" that steering edits.

Causal self-attention, 6 heads

4 × 384² = 590k params per block

Each token attends only to earlier tokens (causal mask). 6 heads of 64 dimensions. Uses PyTorch's fused scaled-dot-product attention (tested against an explicit implementation).

SwiGLU feed-forward, hidden 1,024

Shazeer 2020 · 3 × 384 × 1,024 = 1.18M per block

A gated MLP: W2(silu(W1 x) ⊙ W3 x). Standard in modern LLMs; with hidden 1,024 it has about the same parameters as a 4× GELU MLP.

Residual stream, width 384

6 blocks, context 256 tokens

Every block adds its output to a running vector per token. Steering adds α·v to it after a chosen block.

Training

  • Data: 500k TinyStories tokenized (115M tokens); the run used 80M: 4,882 steps × 64 × 256 tokens.
  • Optimiser: AdamW, lr 1e-3, betas 0.9/0.95, weight decay 0.1; 200 warm-up steps then cosine decay to 10%; gradient clipping 1.0; fp16 mixed precision.
  • Hardware: one free Kaggle T4, about 86k tokens/s, 18 minutes.
  • Result: validation loss 1.67 (perplexity 5.3); coherent stories ("Lily … went to the park to play with her friends … saw a pretty butterfly").
  • Checkpoints every 500 steps; for E6 the first 600 steps were re-run with the same seed and schedule, saving every 50 steps. The re-run reproduced the original validation losses (2.861 at step 250, 2.412 at 500).
  • Also supported, not used in the final run: learned / sinusoidal / ALiBi / no position encoding, LayerNorm, post-norm, GELU, grouped-query and multi-query attention. 52 unit tests cover parameter count, causality, fused vs explicit attention, longer-than-training contexts, and overfitting a batch.

Why TinyStories?

Eldan & Li (2023) showed that models under 10M parameters can write fluent stories if the data uses only words a 3–4-year-old knows. That lets a from-scratch model train in minutes and still produce text worth steering. The price: TinyGPT only knows children's English, so many concepts (economics, old people) don't exist for it.

E1 · Which layer? (Qwen)

Unsteered +0.05. Layer 4: +0.85 at α +8, −0.46 at α −8 (perplexity 10.3 vs 3.6). Layer 14 gives the strongest push to happy (+0.93) but a weak push to sad (−0.28). Random vectors stay between −0.10 and +0.29 across layers. Probe AUC: 0.76 at layer 0 → 0.99 at layers 9–14 → 0.91. Most readable in the middle, most steerable early.

E2 · How hard to push?

S-curve. Towards happy Qwen saturates at +0.96–0.97 for α 12–16, but perplexity rises to 21 and 38. Towards sad the effect peaks at α −12 (−0.62) and weakens at −16 (−0.51) as text breaks into loops. Both models cross 3× perplexity between |α| 8 and 12: that is the usable range.

E4 · How many pairs?

Five pairs give +0.80 / −0.56 (three random subsets), as strong as 150 pairs (+0.85 / −0.46). The vector itself settles more slowly: cosine to the 150-pair vector is 0.84 with 5 pairs, 0.91 with 10, 0.97 with 25. A rough direction is enough to steer.

Probe AUC 0.90–0.97 at every layer. Unsteered already +0.48 (TinyStories end happily). Layer 4: +0.93 / −0.56, perplexity 5.9 / 4.9 vs 2.5. From |α| 16 it breaks (perplexity above 90). A 12M model trained for 18 minutes steers like a 494M one, at the same relative depth.

Five patterns that explain the table

  1. The vector is whatever differs between the examples. Uncertain sentences were also longer and ended in "?", so "confident" became "flat statements". Cat sentences also purred, drank milk and climbed trees, so "cat" became owls and tea. Pairs that differ only in the concept fix it.
  2. You can only steer towards what the model has seen. No old people in TinyStories; few put-downs in Qwen's data. Where one side is the model's default (American setting, happy endings), only the other side moves.
  3. Content steers; grammar doesn't. Wealth, age, size, topic shift whole scenes. Tense lives in a few small words that must be in exactly the right place, and a push at every token scrambles them.
  4. The prompt must leave room. "there was a young girl" gives sharing ↔ greedy nothing to share; "Lily found a shiny red ball… Her friend asked to play. Lily" works.
  5. There is a sweet spot. French: concept score −1.21 at α −4, only −0.36 at −8. Same as E2.

  • No example sentence mentions a dragon or a fairy: the model's own knowledge connects the two directions to a creature that is both. The steering version of king − man + woman ≈ queen.
  • The two directions are almost orthogonal: cosine −0.03 (huge/magic), −0.06 (rich/old on Qwen), so each moves its own concept without disturbing the other.
  • On Qwen ("My neighbour"): poor + old → "so poor that he cannot buy anything… I give him a piece of bread"; rich + old reads mostly as old. "The house at the end of our street": rich + old → "treasures… heirlooms", poor + old → "very dilapidated… I am lonely… I am hungry… I am cold".
  • Strength 8 per concept breaks more often: two orthogonal pushes of 8 add up to √2 × 8 ≈ 11, past the usable range.
Surprises

Interesting observations

  • Reading ≠ pushing. The probe peaks at layers 9–14, but steering works best at layer 4. An early push passes through 20 more blocks that turn it into word choices; a late push has little room left.
  • Happy is easier than sad in both models (Qwen layers 8–10 are the exception). Training data leans positive; pushed hard towards sad, models fall into loops before reaching strongly negative text.
  • "Sad" means scary to TinyGPT: "He thought loud loud so loud mean loud noises or scary…". In children's stories the negative side is a loud dog or a broken toy, not grief. The direction is real, but its meaning comes from the data.
  • Happy steering ends TinyGPT's stories sooner. The end-of-story probability goes from 0.05 (α 0) to 0.26 (α 8) and 0.36 (α 12): happy endings are where stories stop.
  • The concept appears suddenly (E6), not gradually.
  • Qwen loves quizzes: short third-person prompts turn into "Given the context… Possible answers:" or "A. B. C. D. Answer:", with or without steering.
  • Cats became owls and tea: the first cat examples differed in actions, and the vector learned those instead of "cat". The fragment "per per per" is the start of purred.
  • The model's default world is American; steering towards Indian works, towards American changes little.
  • Concepts compose: huge + magic = dragon.
  • Topic is a switch, tone a slider: formal ↔ casual shifts gradually across strengths; food ↔ sports only flips at ±8.

Strengths

What went well

  • Controls everywhere: every steered setting has a random same-size vector; baselines use the same prompts and seeds.
  • An independent judge for sentiment, and a fluency cost reported next to every effect.
  • Owning the whole model: TinyGPT made E6 possible, a question papers on pretrained models can't ask.
  • Reproducible: E6's re-run matched the original losses; the demo's strips are deterministic per seed, and the project page shows the exact texts the demo produces.
  • Cheap: about 2 GPU-hours on free Kaggle, everything else on a laptop CPU.
  • Honest failures: we kept and explained what didn't work (tense, confident, cats, old on TinyGPT).
  • Deployed for free despite Hugging Face needing PRO for Gradio Spaces: a static page that is always on, plus a live laptop demo it links to automatically.
Be honest

Limitations and assumptions

Limitations

  • One training run, one seed for E6. Other seeds, sizes or datasets could move or smooth the transition.
  • Only sentiment is measured with an independent classifier. E7 and E8 use 1–3 prompts and two seeds per concept, judged by eye.
  • The concept score is circular: it uses the same direction as the steering ("confident" scored well while producing textbook exercises).
  • The classifier was trained on tweets and can misjudge odd or broken text; looping text can still score strongly.
  • Small samples: 100 texts per Qwen setting, 60 per TinyGPT; differences of ±0.1 are noise.
  • Fluency cost: the best setting roughly triples perplexity; this is a research tool, not a polished generator.
  • Simple probe: the steering direction on 40 sentences; a trained logistic-regression probe could read more.
  • Two small models; nothing here shows the same holds for large chat models.
  • Demo filter: the demo blocks Chinese and "____" for Qwen; the experiments did not.

Assumptions

  • Concepts are (roughly) linear directions in the residual stream.
  • The mean difference of contrastive pairs points along the concept, and not along something else that differs between the pairs (E7 shows when this fails).
  • Adding the same vector at every token is a reasonable intervention.
  • The unsteered model's perplexity is a fair proxy for fluency, and 3× is a sensible cut-off.
  • "Layer 4" is comparable across models of different depth (it is early in both).
  • Custom concept vectors are rescaled to the happy/sad vector's length, so α means the same push for every concept.
Takeaways

What I learned

  • Concepts really are directions you can add, and a handful of examples finds them.
  • Where a concept is easiest to read is not where it is easiest to push.
  • A steering vector learns everything that differs between your examples, so writing good pairs matters more than writing many.
  • The training data decides what can be steered and what a concept means to the model.
  • Concepts can appear abruptly during training.
  • Every intervention needs a control, and every effect needs its cost (fluency) reported beside it.
  • Building a transformer from scratch (RoPE, RMSNorm, SwiGLU, BPE, training loop) made every part concrete.
Future work

What else could be tried, and what I'd add

Could have tried

  • More seeds and model sizes for E6, to see if the sudden emergence is general.
  • E6 for other concepts: do topic, size or wealth appear at different points in training than sentiment?
  • An independent classifier per concept (or an LLM judge) instead of reading by eye.
  • A trained logistic-regression probe and comparing its direction with the mean-difference direction.
  • Steering only some tokens (e.g. only the prompt, or decaying α) to keep more fluency.
  • Steering at several layers at once with a smaller α each.
  • Larger or chat models (Qwen 1.5B/7B Instruct), and safety-relevant behaviours like refusal or sycophancy (as in Rimsky et al.).
  • Sparse autoencoders to find concept directions without hand-written pairs.

What I'd add to the demo

  • A fluency (perplexity) number on each output, so the cost is visible live.
  • Vector arithmetic beyond two concepts, and subtracting one (rich − old).
  • A layer heat-map: one prompt steered at every layer side by side.
Story

How the project evolved

  1. Started from a "TinyGPT from scratch" idea with 11 architecture ablations (position encodings, norms, attention variants). Felt generic, and 33 runs with 3 seeds was a lot.
  2. Switched the focus to activation steering: more interactive and a better demo. TinyGPT stayed as the from-scratch model, which also enabled the training-history question (E6). The ablation switches remain in the code and tests.
  3. Ran data, training and all experiments on Kaggle T4s; then re-ran the first 600 steps with dense checkpoints when E6 showed the jump happened early.
  4. Built the Gradio demo; Hugging Face needed PRO for Gradio Spaces, so deployed a static page + laptop demo instead.
  5. Testing the demo myself led to E7 and E8: presets for 12 concepts, the Transition and Mix tabs, and the failure analysis (cats, confident, sunny/rainy dropped).
Practice

Likely viva questions

What is your project, in one sentence?

I change what a language model writes by adding a concept vector to its hidden states during generation, test it on a pretrained 0.5B model and on a 12M GPT I built from scratch, and use my own model's training history to find when the concept appears.

What is the residual stream, and why add the vector there?

The running vector per token that every block reads and adds its output to. Because blocks communicate by addition into this one space, a vector added there is carried into every later layer, so it's the natural place to change what the model "has in mind".

How exactly is the steering vector computed?

Run the positive and negative example sentences through the model, record the residual stream after block ℓ at every token (skipping the first token and padding), average each set, and subtract: v = mean(positive) − mean(negative). One vector per layer.

Why skip the first token?

The first token in transformers gets unusually large activations (it acts as an "attention sink"). Including it would make the average dominated by something unrelated to the concept.

What does α mean? Why ±8?

How many times the vector is added. The vector is used at its natural length (the real gap between happy and sad), so α = 8 means eight times that gap. ±8 was chosen automatically: the largest two-way effect with perplexity under 3× normal.

How do you know it's the concept and not just any push?

The random control: a random vector of exactly the same length at the same layer and strength. It moves sentiment by at most about ±0.3 in no consistent direction, while the concept vector moves it steadily one way (+0.85 / −0.46).

Why is layer 4 best for steering when the probe is best at 9–14?

Reading and pushing are different. A push at layer 4 passes through 20 more blocks that turn a slightly happier hidden state into happier word choices. A late push has little room left to act and must already be in the exact form the final layers expect. Late layers still push happy well (+0.93 at layer 14) but sad poorly.

Isn't steering just a stronger prompt?

No: the prompt never changes. And it works where prompting can't: Qwen base can't follow "write a happy story", so asking gave +0.50 while steering gave +0.85. Both together gave +0.96. The cost is fluency (perplexity 10.3 vs 5.4).

Why does more strength sometimes give less effect?

Past the sweet spot the added vector is as large as the hidden state itself, which pushes it off the region the later layers were trained on. They can't decode it into proper text, so only fragments survive and the text loops. Sad peaks at α −12; French is best at −4.

Why is happy easier than sad?

Training data leans positive (TinyStories almost always end happily; casual web narration leans positive), so the happy side is closer to normal text. Pushed hard towards sad, the models fall into loops before reaching strongly negative text.

Explain the E6 result. Why would a concept appear suddenly?

Up to step 150 the probe is at chance and steering does nothing; by step 250 the probe is 0.91 and steering works. It happens when validation loss falls below about 3.1: the model has learned which words are frequent and starts learning how sentences fit together, which sentiment depends on. One run and one seed, so it needs repeating.

How do you know the early re-run is the same training run?

Same seed, same data order and the same learning-rate schedule (the full 4,882-step cosine schedule, just stopped at 600). Its validation losses matched the original run: 2.861 at step 250 and 2.412 at step 500.

What is the probe, and why AUC?

Project 40 natural sentences (20 positive, 20 negative, none using the pair words) onto the layer's steering direction; ROC AUC measures how well that single number separates them: 0.5 is chance, 1.0 perfect. AUC needs no threshold. Template pairs were rejected because they differ by one word, which even layer 0 separates perfectly.

Why that sentiment classifier?

It's a 3-class model (negative, neutral, positive), so neutral text scores near 0. The 2-class SST-2 classifier we tried first called neutral text negative, which made the baseline look sad and hid steering towards sad.

Why perplexity under the unsteered model, and why distinct-2 too?

The unsteered model is the reference for "normal text"; scoring with the steered model would grade itself. Distinct-2 catches loops, which perplexity misses because repetition is easy to predict.

Walk me through TinyGPT.

BPE tokenizer with 4,096 tokens → 384-dimensional embedding → 6 pre-norm blocks, each RMSNorm → causal attention with 6 heads and RoPE → add, then RMSNorm → SwiGLU MLP (hidden 1,024) → add → final RMSNorm → output layer tied to the embedding. 12,194,688 parameters, trained on 80M TinyStories tokens in 18 minutes, validation loss 1.67.

Why RoPE / RMSNorm / SwiGLU / pre-norm?

RoPE: attention depends on relative distance, no position table. RMSNorm: simpler than LayerNorm, same quality. SwiGLU: gated MLP that works better than GELU at equal parameters. Pre-norm: a clean residual path, stable training. They're the choices modern LLMs (Llama, Qwen) use.

Why a 4,096 vocabulary?

TinyStories uses simple words, so a small vocabulary covers it. A 50k vocabulary would put about 19M parameters in the embedding alone, more than the whole model.

How many pairs do you need?

Five pairs give almost the full effect (+0.80 / −0.56 vs +0.85 / −0.46 with 150). The direction keeps refining (cosine 0.84 → 0.97 by 25 pairs), but a rough direction already steers. Quality matters more than quantity: the cat pairs show that.

Why did confident ↔ uncertain and the first dog ↔ cat fail?

The vector learns every difference between the boxes. The uncertain sentences were longer and ended in "?", so "confident" became "flat statements" (textbook exercises). The cat sentences also described actions (purring, milk, trees), so steering gave owls and tea. Pairs that differ only in the concept word fixed the cats.

Why does old ↔ young work on Qwen but not TinyGPT?

A model can only be steered towards what its training data contains. TinyStories has almost no old characters; Qwen read the web.

Why does tense fail?

Tense lives in a few function words ("will", "-ed") that must appear in exactly the right place; a push added at every token scrambles grammar. Content concepts change whole scenes and survive it.

How does mixing two concepts work, and why does it work?

Add s·(A + B) at the same layer. The two directions are nearly orthogonal (cosine around 0), so each moves its own concept. The model fills in a combination it was never shown: huge + magic → dragon, tiny + magic → fairy. Like king − man + woman ≈ queen.

How do the Transition and Mix tabs keep rows comparable?

All rows share their random draws. TinyGPT reuses the same seed per row. Qwen generates the whole batch with one shared Gumbel noise vector per token (argmax of logits/T plus Gumbel noise is an exact sample from the softmax), so rows differ only because of the steering.

How is it deployed?

A static Hugging Face Space (free, always on) with the findings, figures and a replay of real generations, and a live Gradio app on my laptop with a public gradio.live link. The app writes the link to the Space's live.json so the page's "Live demo" button points at it. Hugging Face now needs PRO for Gradio Spaces.

What are the main limitations?

One training run for E6; only sentiment has an independent metric; the concept score is circular; small samples; fluency cost; two small models.

Is this related to anything you've studied before?

Moving along a direction in a GAN's latent space to morph faces is the same idea; the Transition tab is the text version. And word-vector arithmetic (king − man + woman) is what E8 does with steering vectors.

What would you do with more time?

Repeat E6 with more seeds and sizes and for other concepts; a classifier per concept; a trained probe; steering only some tokens or several layers to save fluency; larger and chat models; sparse autoencoders to find directions without pairs.

How did you use Claude Code?

As a pair programmer for most of the code. I chose the project direction (from TinyGPT ablations to steering), ran everything on Kaggle, decided the experiments and the deployment option, and tested the demo myself; that testing found real issues: the cat side never produced cats, sunny ↔ rainy was weak (dropped), Mix example prompts were too similar, and good showcase prompts.

What was the hardest part?

Choosing honest metrics (the first classifier and the first probe both looked fine and were wrong), and making concepts other than sentiment work, which needed carefully matched pairs and prompts that leave room for the concept.
